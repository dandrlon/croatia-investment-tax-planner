# Phase 1: Web API, Import and Tax Rules – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-user ASP.NET Core Web API that imports a Trading 212 CSV export into SQL Server and reports dividend tax per year and position, the capital-gains exemption date of every lot (FIFO), and the estimated tax if everything were sold today. It ships with xUnit tests, Docker Compose and GitHub Actions.

**Architecture:** There are three projects. `TaxPlanner.Core` holds the domain types, the pure tax rules and the CSV parser, with no database or web dependencies, so every rule can be unit tested. `TaxPlanner.Infrastructure` holds the EF Core `DbContext`, its mappings and the migrations. `TaxPlanner.Api` is the controllers-based Web API: it stores parsed transactions and computes every report on read from the stored transactions. No derived data is persisted.

**Tech Stack:** .NET 10, ASP.NET Core (controllers), EF Core 10 + SQL Server 2022, CsvHelper, xUnit v3, Testcontainers.MsSql, Microsoft.AspNetCore.OpenApi + Swashbuckle.AspNetCore.SwaggerUI, Docker Compose, GitHub Actions.

**Spec:** `docs/design.md`

## Global Constraints

- Target framework `net10.0` for every project. EF Core packages on 10.x.
- All code, comments, commit messages, README and docs are in English. Croatian words appear only as proper names (Porezna uprava, JOPPD).
- Every money amount is `decimal`. `double` and `float` are never used for amounts, quantities or rates.
- All number and date parsing uses `CultureInfo.InvariantCulture`. The author's Windows machine runs with the `hr-HR` culture, where the decimal separator is a comma.
- Monetary results are rounded to 2 decimals with `MidpointRounding.AwayFromZero`, and only at the final summed figure, never per row.
- Every report response (dividends, positions, estimate) carries a `disclaimer` field with this exact text: `"This is not tax advice. Verify all amounts with the Croatian Tax Administration (Porezna uprava) before filing."`
- Only EUR-denominated Trading 212 accounts are supported. A row whose `Currency (Total)` is not `EUR` is an error, never a silent conversion.
- The author's real CSV export must never be committed. Test fixtures are synthetic files that use the real header.
- Single user: no auth, no user IDs in the schema.
- Assertions use plain xUnit `Assert`. Do not add FluentAssertions, whose v8 licence is commercial.

## Assumptions this plan relies on (Task 0 confirms or corrects them)

The spec says to verify the tax rules and the CSV format before implementing. The plan pins these working values. If Task 0 finds otherwise, change the value in the one place named here before starting the dependent task.

| # | Assumption | Single place it lives |
|---|-----------|------------------------|
| A1 | The capital income tax rate is 12% for years 2024 onward. Earlier years have no configured rate (the author confirms the 2023 rate and surtax rules before adding it). | `TaxRates` (Task 2) |
| A2 | Foreign withholding tax is credited per dividend payment, up to the Croatian tax on that payment: `credit = min(withheld, gross × rate)`. | `DividendTaxCalculator` (Task 2) |
| A3 | A lot is exempt when sold **more than** 2 years after acquisition, so the exemption date is `acquiredOn.AddYears(2).AddDays(1)`. | `HoldingPeriod` (Task 1) |
| A4 | The acquisition and payment date is the Croatian local date (`Europe/Zagreb`) of the T212 `Time` column, which is UTC. | `CroatianCalendar` (Task 1) |
| A5 | In a T212 dividend row, `Total` is the net amount in EUR and `Withholding tax` is a positive amount in `Currency (Withholding tax)`. Gross = Total + withholding in EUR. | `Trading212CsvParser` (Task 5) |
| A6 | `Exchange rate` is units of instrument currency per 1 EUR, so a USD amount converts as `usd / rate`. | `Trading212CsvParser` (Task 5) |
| A7 | EUR amounts use T212's own `Total` (its applied rate, including FX fees) instead of HNB/ECB reference rates. This is documented as a known limitation. | `docs/tax-rules.md` (Task 0) |
| A8 | The cost basis of a buy is its `Total` in EUR. The proceeds of a sell are its `Total` in EUR. | `FifoLotMatcher` (Task 3) |

## Review Focus

1. **Croatian locale.** On an `hr-HR` machine, `"12.5"` must still parse as 12.5, not 125 and not an error. Tested in Task 5 with `CultureInfo.CurrentCulture = new("hr-HR")`.
2. **Re-importing an overlapping export.** Users export "all time" again next year. Rows already stored must count as duplicates and must not double the dividends. Tested in Task 6.
3. **Export that starts mid-history.** A sell larger than the shares held must produce a warning and match only what exists. It must never produce a negative lot or a crash. Tested in Task 3.
4. **Midnight UTC near a boundary.** A buy at `2024-12-31 23:30:00` UTC is acquired on 2025-01-01 in Zagreb, which changes both its tax year and its exemption date. Tested in Task 1.
5. **Years without a verified rate.** A 2023 dividend must show a `null` tax and a warning. It must not show a silent 12%. Tested in Task 2.

**Interfaces:**

  - `static SaleEstimate SaleEstimator.Estimate(LotMatchResult lots, IReadOnlyDictionary<string, decimal> pricesEurByIsin, DateOnly today)`

The rule is "Gains and losses within the same calendar year are offset against each other" (spec). `Realized` is the sum of `GainEur` over the non-exempt disposals with `DisposedOn.Year == today.Year`. `Hypothetical` is the sum, over the open lots that are not exempt on `today`, of `price × qty − CostEur`. `EstimatedTaxEur = rate × max(0, Realized + Hypothetical)`, rounded once. Gains and losses on exempt lots do not enter the offset.

### Task 5: Trading 212 CSV parser

**Files:**
- Create: `src/TaxPlanner.Core/Import/Trading212CsvParser.cs` (add the `CsvHelper` package to Core)
- Create: `tests/TaxPlanner.Core.Tests/Fixtures/sample-export.csv`. Use the real header from `docs/trading212-csv.md`. Set the file to copy to the output directory.
- Test: `tests/TaxPlanner.Core.Tests/Import/Trading212CsvParserTests.cs`

**Interfaces:**
- Consumes: `Transaction`, `TransactionType`
- Produces:
  - `static ParseResult Trading212CsvParser.Parse(Stream csv)`
  - `record ParseResult(IReadOnlyList<Transaction> Transactions, IReadOnlyList<SkippedRow> Skipped, IReadOnlyList<ParseError> Errors)`
  - `record SkippedRow(int Line, string Action, string Reason)`, `record ParseError(int Line, string Message)`. Line numbers are 1-based file lines, and the header is line 1.

Columns are mapped **by header name**, never by position, because T212 omits columns it has no data for. The required columns are `Action`, `Time`, `ISIN`, `Ticker`, `Name`, `No. of shares` and `Total`, plus `Currency (Total)`. If one is missing, the parser returns a single `ParseError(1, "Missing required column '{name}'")` and no transactions. Action mapping (case-insensitive): an action ending in `buy` maps to Buy, one ending in `sell` maps to Sell, and one starting with `Dividend` maps to Dividend. Anything else becomes a `SkippedRow` with reason `"Not a trade or dividend"`. `Time` is parsed with the formats `yyyy-MM-dd HH:mm:ss` and `yyyy-MM-dd HH:mm:ss.fff` as UTC. Withholding is converted to EUR with `Math.Abs(amount)` when its currency is EUR, and with `Math.Abs(amount) / ExchangeRate` otherwise (A6). If withholding is non-EUR and the exchange rate is missing, that is a row error. `SourceHash` is the lowercase hex SHA-256 of `"id:" + ID` when `ID` is non-empty, and otherwise of `Action|Time|ISIN|No. of shares|Total`.
