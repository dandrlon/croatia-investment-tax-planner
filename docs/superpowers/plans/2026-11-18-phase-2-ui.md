# Phase 2: Web UI – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-page Angular UI, served by nginx in Docker Compose. It shows the last import, lets you upload a new Trading 212 CSV, and shows dividend tax, the next exemption dates and the positions, using only data the existing API returns plus one new endpoint for the last import.

**Architecture:** The API gains `ImportBatch.ErrorCount` and `GET /api/imports/latest`. A new Angular workspace in `src/TaxPlanner.Web` has these parts:
- one typed API service;
- pure TypeScript helpers for anything the UI selects or formats (unit tested without Angular);
- small presentational components;
- a `DashboardComponent` that loads the data and reloads it after an upload.

nginx serves the built app and forwards `/api`, `/swagger` and `/openapi` to the API on one origin.

**Tech Stack:** .NET 10 / EF Core 10 (existing). Angular 22.2.5 with standalone components and signals. Angular Material 22.2.5. Vitest, the Angular CLI default test runner. Node 24 LTS. nginx (alpine). Docker Compose. GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-phase-2-ui-design.md` (builds on `docs/design.md`)

## Global Constraints

- All UI text, code, comments and commit messages are in English.
- The UI never calculates tax. It only formats API values and selects among them: the current and previous year, and the earliest future exemption date.
- Use plain Angular: standalone components, signals and `HttpClient`. No NgRx and no other state libraries.
- Angular and `@angular/material` are pinned to `22.2.5`, which is at least two weeks old. Node is 24 LTS, because Angular 22 needs `^22.22.3 || ^24.15.0`.
- Amounts are formatted as `€14.62` (EUR, 2 decimals). Dates are formatted as `3 Mar 2027`. An import timestamp is `18 Nov 2026, 14:02` in the browser's local time.
- The disclaimer comes from the API response's `disclaimer` field and is shown on every page state that has data, including the empty state.
- No existing API response shape and no tax rule changes. The API only adds `GET /api/imports/latest` and the `ErrorCount` column.
- The page must have no horizontal scroll at a 375 px width. Tables may scroll inside their own container.
- `web` is published on `localhost:8080`. `api` publishes no host port. nginx `client_max_body_size 11m`.

## Review Focus

1. **Dates shift by a day in a browser west of UTC.** `"2027-03-03"` must render as `3 Mar 2027` whatever the time zone. Covered in Task 3 by formatting date strings without `new Date()`.
2. **The API is down, or an upload returns a 500.** The page shows a message and a Retry button. It is never blank and never stuck on a spinner. Covered by tests in Tasks 4 and 6.
3. **A double click while uploading.** The button is disabled while an upload is in flight, so only one request goes out. Covered by a test in Task 4.
4. **A real export of several MB through nginx.** It must reach the API, not get a 413 from nginx. Covered by a manual check in Task 7.
5. **Re-uploading the same file.** The bar shows the new batch with `0 new` and the duplicates count, and the numbers stay the same. Covered by a test in Task 4 and an integration test in Task 1.

### Task 3: Formatting and selection helpers

**Files:**
- Create: `src/app/shared/format.ts`, `src/app/shared/summary.ts`
- Test: `src/app/shared/format.spec.ts`, `src/app/shared/summary.spec.ts`

**Interfaces:**
- Consumes: the `models.ts` types
- Produces from `format.ts`:
  - `formatEur(value: number): string` uses `Intl.NumberFormat('en-IE', { style: 'currency', currency: 'EUR' })`.
  - `formatIsoDate(isoDate: string): string` splits `yyyy-MM-dd` into its parts with fixed English month abbreviations. It never constructs a `Date`.
  - `formatTimestamp(isoUtc: string): string` formats as `d MMM yyyy, HH:mm` in local time.
- Produces from `summary.ts`:
  - `type TileValue = { kind: 'amount'; eur: number } | { kind: 'unverified' }`
  - `taxDueForYear(years: DividendYear[], year: number): TileValue`. A missing year gives `{amount, 0}`, and `taxDueEur === null` gives `unverified`.
  - `nextExemption(position: Position): { date: string; quantity: number } | null`. It takes the earliest `exemptFrom` among lots with `!isExemptToday` and sums the quantity of the lots with that date. It returns `null` when every lot is exempt.
  - `nextExemptionOverall(positions: Position[]): { ticker: string; date: string; quantity: number } | null`
  - `collectWarnings(dividends: DividendsResponse, positions: PositionsResponse): string[]`. It collects the year warnings in year order, then the position warnings, without duplicates and keeping the first occurrence.
  - `currentYear(now?: Date): number`

### Task 4: Import bar and upload

**Files:**
- Create: `src/app/import-bar/import-bar.component.{ts,html,scss,spec.ts}`

**Interfaces:**
- Consumes: `TaxApiService.uploadCsv`, `ImportSummary`, `ImportResult`, `formatTimestamp`
- Produces: `ImportBarComponent` (selector `app-import-bar`) with:
  - `summary = input<ImportSummary | null>()`
  - `uploaded = output<ImportResult>()`
  - internal signals `uploading`, `lastResult: ImportResult | null` and `error: string | null`

**Behaviour:**
- **With a summary**, the bar shows `fileName`, `formatTimestamp(importedAtUtc)` and `"{importedCount} new · {duplicateCount} already imported · {skippedCount} skipped · {errorCount} errors"`. When `errorCount > 0`, the error part has the CSS class `warn`.
- **Upload button.** The button `Upload new CSV` opens a hidden `<input type="file" accept=".csv">`.
- **Client-side checks.** An empty file gives the error `The file is empty.` and a file over 10 MB gives `The file must be 10 MB or smaller.`. Neither case sends a request.
- **During an upload**, `uploading` is true, the button is disabled and an indeterminate `mat-progress-bar` is shown.
- **On success**, the component sets `lastResult`, emits `uploaded` and shows `"{imported} new, {duplicates} already imported, {skipped.length} skipped, {errors.length} errors"`. It also lists each error as `Line {line}: {message}`.
- **On failure:**
  - A `400` shows `problem.detail ?? problem.title`.
  - A status of `0` shows `Could not reach the server. Try again.`.
  - Any other status shows `The upload failed (HTTP {status}). Try again.`.
  - In every case `uploading` becomes false.
